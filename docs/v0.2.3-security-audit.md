# v0.2.3 security audit closure

Last local verification: 2026-07-29.

The audit reviewed baseline commit `65674b7743e1ab00538a45b3eae605b2441b5afa`.
The release tag must target the exact commit that passed the final gates below.

No SSH, Tailscale, or firewall Apply was run on the development workstation or
a remote host.

## Release decision

The six code-level P0 release blockers found by the audit are remediated. The
Windows-native and artifact gates passed on 2026-07-29, so `v0.2.3` is approved
for publication within the validation boundary below.

## P0 closure matrix

### 1. Verify false success

Effective SSH authentication, the supported authorized-key path and content,
service/port state, and firewall evidence are now checked independently. Unknown
evidence fails closed.

Evidence: `TestVerifyFailsClosedOnInvalidSSHOrFirewallEvidence` and
`TestInvalidSSHConfigurationAndMissingAuthenticationCannotVerifyAsReady`.

### 2. Firewall false safety

Firewall state now distinguishes checked, enabled, unknown, and error states.
Provider, port, and normalized CIDR sets must match exactly; broad or additional
exposure is a blocker.

Evidence: `TestFirewallUnknownOrUnexpectedScopeBlocksApply` and
`TestBroadWindowsFirewallRuleIsAConflict`.

### 3. Mutable confirmed Plan

A canonical Plan SHA-256 is required by CLI, desktop, and the elevation
protocol. State, profile, or command drift invalidates confirmation.

Evidence: `TestApplyRequiresTheReviewedPlanDigest`, Plan digest tests, and
elevation protocol tests.

### 4. Rollback and exit-code failures

Journal setup/read failures return nonzero. Journal progress is atomically
persisted with an integrity digest; tampering and symlinks/reparse points are
rejected, and on unix the journal must be owned by the current user and not
group/world-writable. Repeated rollback does not execute completed commands.

Evidence: journal, rollback, process-exit, and cross-platform build tests.

### 5. Unverified offline installer

Offline execution requires a normalized SHA-256. Links and non-regular files are
rejected; bytes are copied and hashed into controlled staging, and only the
staged artifact executes.

Evidence: offline profile, planner, and executor tests.

### 6. Recursive NSIS uninstall

The application uses a fixed install directory. The uninstaller deletes only
owned files and removes directories only when empty.

Evidence: `TestWindowsInstallerCannotRecursivelyDeleteInstallDirectory` and the
checksum-verified v0.2.0-to-v0.2.3 native upgrade/uninstall smoke.

## Post-audit simplifications

After the audit closed, three defensive mechanisms were reviewed as
over-engineered relative to the documented threat model and simplified on
purpose (the full-hardening implementation is preserved on the
`archive/v0.2.3-full-hardening` branch):

- Effective-SSH probing no longer runs a per-connection `sshd -T -C` matrix;
  a single global `sshd -T` dump is used and `Match`-dependent policy fails
  closed as unchecked (see `docs/platform-support.md`).
- The Windows rollback-journal owner-SID check was dropped; reparse-point and
  directory rejection remains as parity with the unix `O_NOFOLLOW` checks.
- The interactive process lock no longer uses random tokens and
  compare-before-delete; it is an exclusive-create PID file with stale-PID
  recovery, and the residual unlock race is accepted as harmless.
